# KNOWN_ISSUES

Известные ограничения и «потолки» текущих реализаций. Если пункт перестал быть
актуален — удали его отсюда и отметь в CHANGELOG.

## Функциональные

1. **`/myorders` показывает только активные заказы, без пагинации.** Список
   растёт вместе с историей покупок; при десятках заказов сообщение станет
   длинным. Потолок всерьёз не наступает (одно-два сообщения), пагинация не
   делалась — добавить, если пользователи жалуются.
   *Upgrade:* inline-клавиатура со страницами.

2. **Меню «обновить заказ» показывает первые 3 активных заказа**
   (`telegram_bot.py`, `callback_data="update_existing"`). Остальные недоступны
   для обновления из меню, но сами заказы не теряются (видны в `/myorders`).
   *Upgrade:* кнопка «показать ещё».

3. **Оплата звёздами (XTR) не имеет рефандов.** После оплаты звёзд возврат
   средств возможен только вручную (Telegram не предоставляет API-рефанд для
   ботов). Это осознанное ограничение платформы, не баг кода.

4. **Бот поддержки пересылает вопросы владельцу** и раздаёт готовые ответы по
   шаблонам; живой оператор не в чате 24/7. Ограничение бизнес-модели.

## Технические

5. **Нет полноценного typecheck/linter со стилем** — только фатальные проверки
   ruff (см. ASSUMPTIONS #1–2). Рефакторинг типов — отдельная инициатива.

6. **Две рабочие копии сайта** (Default Project и репозиторий) могут разойтись,
   если править файлы вне `deploy_site.ps1`. Проверено 2026-09-27: идентичны.
   *Upgrade:* единственный источник + `git diff`-гайд в деплое.

7. **Локальный polling бота невозможен при работающем проде** (`409 Conflict`).
   Для локальной отладки использовать тесты или бота поддержки на другом сервере.

8. **CI не имеет отдельного smoke-слоя против живого сайта/бота** (только
   статические проверки). Живые 200-проверки — ручные (деплой-скрипт + ручные
   API-пробы). *Upgrade:* scheduled workflow `curl` к Pages и к боту.

## Окружение

9. **Тесты зависят от состояния `payments.db`** в рабочем каталоге: флаки по
   количеству заказов/оплат возможны, если сторонние данные лягут в ту же базу.
   2026-09-27 найден и устранён последний такой случай (`/myorders`). CI всегда
    свежий (db нет в checkout: в gitignore).
